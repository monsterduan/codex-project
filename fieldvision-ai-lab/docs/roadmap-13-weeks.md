# 13 周学习与交付路线

每周 25–30 小时：约 8 小时基础与独立练习、12–15 小时实现、5–7 小时评测与复盘。时间不足先保主项目，不能用未测结果补齐里程碑。

| 周次 | 学习重点 | 项目交付和验收 |
|---|---|---|
| 1 | Python 模块、类型、异常、迭代器、测试、Git | 跑通首版；不看助手独立重写 CSV 最佳同轮选择；解释一个失败输入 |
| 2 | Transformer 注意力、token、上下文、推理参数；HTTP | 接入自己控制的真实模型服务；记录超时、失败与 token；能解释 system/user 和上下文数据区别 |
| 3 | 文档清洗、分块、稀疏检索、BM25 | 整理 30–50 份有权使用的工程资料；记录来源；构造至少 60 条问题，按文档来源隔离开发和测试 |
| 4 | embedding、余弦相似度、向量索引 | 实测一个本地语义模型；固定切分和数据，对比 BM25 与语义检索；保留失败例，不只报均值 |
| 5 | RRF、重排序、Recall/MRR、拒答 | 在固定题集比较词法/语义/融合；增加同主题无答案、冲突、注入案例；发布第一份消融报告 |
| 6 | 提示设计、结构输出、模型评测 | 人工盲评至少 50 条未参与调参的问题；按引用支持、正确拒答、错误结论、延迟和成本分类；主项目里程碑 v0.2 |
| 7 | 实验设计、数据泄漏、配置与版本 | RunLens 导入可公开的真实日志；记录数据划分哈希；整理一组可以复现的对照，不反向补写历史配置 |
| 8 | 多种子与误差分析 | 对一个有价值的视觉改动做固定条件重复实验；输出原始日志、均值/离散程度及失败案例；算力不足则报告限制 |
| 9 | LoRA/QLoRA、SFT 数据划分与过拟合 | 可选：用 LLaMA-Factory 做小模型结构化故障摘要任务，对比基础模型/提示/RAG/SFT；若没有数据与算力则改为深做检索评测 |
| 10 | ONNX、执行提供程序、预处理/后处理、性能统计 | 对自己模型做真实 CPU 或 GPU 基准；确认导出前后精度；Jetson/昇腾只有实际拿到设备并测量后才写入结果 |
| 11 | FastAPI、配置管理、测试分层、CI | 三模块共用证据格式；修复真实使用问题；在 Linux/Windows 跑测试；录制操作演示，模型和依赖版本可复现 |
| 12 | 需求分析、文档、技术表达 | README、数据卡、评测表、3–5 分钟视频、面试问答；请同学在新环境复现一次并记录问题 |
| 13 | 补缺、模拟面试、投递 | 修复复现失败；用实际测得的结果改写简历；每个重要结论能指出原始数据和自己写的代码 |

## 最终验收标准

1. 新环境按 README 安装后，离线模式能运行；模型服务失败时不伪装成功。
2. 主项目有独立测试题、逐条错误分析和引用核查，不把当前 20 条演示回归题当最终成绩。
3. 至少一份真实、有权限公开的工程数据证据；无法公开时提供可运行的脱敏样例和采集方法，说明限制。
4. 一个可复现视觉实验对照或一个真实推理基准，至少完成其一；所有成绩包含模型、数据、输入、设备和版本条件。
5. 能独立解释分块、检索、融合、证据门槛、同轮选择和性能计时边界，并现场修改其中一个模块。
6. 开源版本有测试、许可、依赖锁定、失败示例和已知限制；不以提交次数或 star 数替代能力证明。

参考学习材料：[LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)、[Sentence Transformers](https://sbert.net/docs/package_reference/sentence_transformer/model.html)、[Qwen3-Embedding](https://github.com/QwenLM/Qwen3-Embedding)、[LLaMA-Factory](https://github.com/hiyouga/LlamaFactory)、[ONNX Runtime](https://onnxruntime.ai/docs/api/python/api_summary.html)。
